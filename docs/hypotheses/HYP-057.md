# HYP-057: monotone rating expert для unmatched H70 fallback

- Дата:2026-10-24, Москва; развитие исходной **предложенной, не проверенной** [H57](HYP-049-068-proposals.md).
- Спецификация: [SPEC011](../specs/SPEC-011-three-hour-improvement.md), REQ1101–1104, REQ1107–1109.
- Статус: один design/config зафиксирован до fit, реализация и синтетические unit-проверки готовы; реальных fit/score при передаче нет.
- Основание: координатор прямо поручил данный semantically monotone experiment. Отрицательное направление rating является **согласованным исследовательским допущением**, не установленным причинным законом; исходная H57 запрещала объявлять такой закон без обоснования.

## Утверждение и новизна

Ограничение класса допустимых функций по raw ENERGY STAR rating может уменьшить неустойчивость глобального прогноза там, где нет unambiguous past H70 profile donor. Высокий energy efficiency rating мотивирует отрицательный знак только как modeling assumption при фиксированных прочих признаках; данные могут нарушать это предположение. Новизна — формальное monotone constraint, не missing-gate H90, building-class/log experts H35 или whole-task router H41. H57 не переименовывает оценённый метод.

## Единственная конфигурация до запуска

`MonotoneUnmatchedRegressor(threads=2,fit_hook=None)`; API `fit(X,y,base_predictor=None)`, `predict`, `configuration`, `audit_`.

1. Требуется переданный совместимый cached H70high predictor; его fit не вызывается. Profile index использует все fit X, без y: canonical State_Factor/building_class/facility_type/floor_area/year_built, всякий sameyear collision отвергает весь profile. Query считается matched только если retained profile имеет year<queryYear.
2. Эксперт обучается только на finite numeric energy_star_rating строках, включая rating0. Numeric coercion перед feature fitting гарантирует, что rating остаётся числовым при исходном object/string dtype. Target finite,≥0, исходные единицы. Minimum300 known-rating training rows; меньше →нет learner и baseline unchanged.
3. FeatureComposition **только29/30** (wind/temperature), fit только на known subset. H31 запрещена здесь: derived rating-relative feature обошла бы raw-rating constraint. ID/target/label исключены из expert input. Encoder(native=True,scale=False) fit только на subset; numeric inf→NaN и fit medians, categorical levels fit-only, unknown category→missing category code.
4. LightGBMRegressor: n_estimators700,learning_rate.04,num_leaves31,min_child_samples40,reg_lambda10,objective=regression (original squared error),n_jobs2,random_state42,verbosity−1; monotone_constraints_method='basic'. Constraint vector формируется **по фактическому native encoded column order**: raw energy_star_rating−1, каждый другой feature0. Ни target log transform, ни outlier deletion, ни validation earlystop нет.
5. Query gate: finite numeric rating **и нет unambiguous strictly-past profile**. При gate и обученном model output=.7*max(expert_prediction,0)+.3*cached H70 prediction. Все missing-rating/matched query rows остаются baseline побитно; zero rating observed. Unknown/ambiguous profile допускается к эксперту. Query не меняет index/model statistics.
6. fit_hook(estimator,actual_known_subset_native_frame,subset_y,configuration,**fit_kwargs) может зарегистрировать actual learner до его fit; subset mask/positions/original indices, feature columns и constraint vector сохраняются в audit. При сериализации hook удаляется, чтобы closure не ломала pickle. Обучающий target не входит в matching key или preprocessing statistics.

Формальная monotonicity относится к **expert function при фиксированных остальных features**, не к смеси с произвольным H70 baseline и не к изменению gate/физического объекта. В тесте constant baseline/raw features и unmatched keys дают monotonic blended rating grid. Производственный baseline может иметь собственную немонотонность, поэтому overall guarantee не заявляется.
