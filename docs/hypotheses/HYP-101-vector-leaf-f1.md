# HYP-101: общие векторные листья и точный soft Macro-F1

Статус: proposed, единственная конфигурация заморожена до запуска на датасете.
HYPOTHESES.md прочитан перед реализацией; повторов H72/H80/H92 нет: они
используют MLP либо отдельные скалярные деревья. Новый механизм — единое
разбиение пространства признаков для всех компонент вектора классов в каждом
дереве XGBoost; каждый лист обновляет все K логитов одновременно.

## Замороженный алгоритм и проверка

`VectorLeafTeacherBoost`: XGBoost **установленной версии 2.1.4**, без обновлений
и внешних зависимостей; `xgb.train`, `multi_strategy=multi_output_tree`,
`tree_method=hist`, CPU, 300 раундов, depth6, eta.05, lambda5, alpha0,
min_child_weight1, gamma0, max_bin256, subsample1, все colsample1,
seed42, nthread2. Не grid и не подбор числа раундов по query.
Ограничение 900 секунд суммарно на гипотезу, включая outer; превышение
прерывает запуск без оценки частичной модели. Runner отвечает за общий бюджет.

Исходные признаки обрабатываются `TrainOnlyEncoder` H72: медиана только fit,
log1p неотрицательных fit-колонок, стандартизация и clip8, OHE с игнорированием
неизвестных категорий. Ни target encoding, ни статистик query нет. Все строки
сохраняются. Порядок teacher-колонок строго `np.unique(y)`; DataFrame проверяется
по именам. Teacher нормируется построчно, log clip1e-12 задаёт `base_margin`.

Пусть p=softmax(z), Y — one-hot, T_c=sum_i Y_ic*p_ic,
D_c=sum_i Y_ic+sum_i p_ic+1e-8. Оптимизируется ровно
L=.5*mean_i(-log p_i,y_i)+.5*(1-mean_c(2T_c/D_c)).
Используется точный полный градиент H72 с цепным правилом softmax, умноженный
на N для суммируемых обновлений XGBoost. Диагональная кривизна
`max(.5*p*(1-p),.001)` — положительный численный суррогат, **не точный Hessian**
и не доказанная верхняя граница; гарантии уменьшения не выписываются.
Балансировки классов и вторичной коррекции решений нет.

Query DMatrix получает собственный teacher logp; `predict(output_margin=True)`
**уже включает этот margin**, поэтому поверх возвращённых логитов применяется
только softmax. Нулевое число раундов — технический тест без learner-fit,
возвращающий teacher без float32-квантования. Реальный XGBoost хранит margin
float32: для ненулевой модели ожидается эта стандартная точность.

## Честный teacher и критерий

Inner: переиспользовать завершённые H88 три сгруппированных nested RAW OOF
cache без новых базовых fit; query — существующий независимый RAW fold0.
Outer: те же RAW OOF-вероятности для fit и независимый RAW query. H48 сравнивается
отдельно; его in-sample мета-выход не заменяет честный train teacher.
Целевой общий критерий SPEC011: outer Macro-F1 >=.7794373944089334;
inner улучшение относительно RAW teacher .5873380697311004 — только отбор,
не доказательство достижения outer-цели. Старый просмотренный outer exploratory.

## Совместимость и TDD до научного запуска

Синтетический 60x4, K=3, два раунда на установленной версии 2.1.4 успешно
принимают NxK градиент/Hessian, при целочисленной одномерной DMatrix.label.
API не требует альтернативы multioutput-regression или обновления пакета.
Тесты проверяют реальные два дерева с size_leaf_vector=3, точный градиент
центральными разностями, однократный query margin, нулевой baseline,
неизвестные категории, JSON/pickle, batch/permutation и строгую class alignment.
Производственных датасетов эти проверки не обучают; качества гипотезы пока нет.

Официальные исходники документации именно тега v2.1.4:
[vector leaf](https://github.com/dmlc/xgboost/blob/v2.1.4/doc/tutorials/multioutput.rst),
[parameters](https://github.com/dmlc/xgboost/blob/v2.1.4/doc/parameter.rst).
Функция экспериментальная с ограниченной поддержкой возможностей; проверены
только нужные здесь train, margin prediction и JSON/pickle, не SHAP/другие API.
