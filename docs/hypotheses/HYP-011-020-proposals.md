## HYP-011 — XGBoost с histogram-обучением

Обе задачи. Предположение: ещё не проверенное семейство даст лучший баланс ошибки и сложности. Предложенная первая конфигурация: XGBoost2.1.4, tree_method=hist,600 деревьев, depth6, learning_rate0.05, reg_lambda1, seed42; median/one-hot только по train. Регрессия — squared error, классификация — multi:softprob с обратным отображением labels. Новизна: XGBoost отсутствует в истории; это не повтор CatBoost/LightGBM. Критерий — общие пороги отдельно для каждой задачи. Риск: время многоклассового обучения; до реализации проверить импорты в ML-окружении, пакет разрешён исходным requirements.

## HYP-012 — Обучение на log1p таргета

Регрессия, ExtraTrees с конфигурацией HYP-010. Предположение: преобразование именно y уменьшит влияние длинного правого хвоста при обучении. Использовать log1p(y), после predict — expm1, RMSE считать в исходных единицах; предварительно проверить область допустимых значений. Новизна: ранее Gaussian-преобразования касались X, а не y. Риск: обратное преобразование может систематически занижать условное среднее и ухудшить RMSE; это проверяемая гипотеза, не гарантированное улучшение. Внутрисемейный контроль — сохранённый ExtraTrees43.567568, практический порог —43.004639.

## HYP-013 — Tweedie objective

Регрессия, LightGBM HYP-009 с objective=tweedie и tweedie_variance_power=1.5; остальные настройки прежние. Предположение: иная модель зависимости среднего и дисперсии лучше опишет положительный асимметричный target. До fit проверить неотрицательность y и наличие положительных значений; оценивать исходный RMSE. Новизна: меняется функция потерь, а не сила L1/L2. Риск: Tweedie-loss может улучшиться без выигрыша RMSE. Само улучшение относительно слабого LGBM60.492688 ещё не делает модель лучшей.

## HYP-014 — Линейные модели внутри листьев

Регрессия, LightGBM с linear_tree=true и стандартизацией числовой части по train, при сохранении категорий. Предположение: линейные листья лучше переносят погодные зависимости на будущий год. Новизна — архитектура листа; отдельный StandardScaler для обычных деревьев уже проверен и не запускается снова. Критерий — общий RMSE-порог; контролировать RAM/время. Риск: численная нестабильность зависимых признаков и увеличенная память; не совмещать с новой VIF-проверкой в том же опыте.

## HYP-015 — Target encoding с исключением собственных меток

Регрессия, ExtraTrees: категориальные признаки заменить сглаженными оценками target, остальные входы и параметры не менять. Предположение: такая числовая статистика лучше передаст различия категорий, чем one-hot. Обучающие кодировки получать out-of-fold только внутри fit, не допуская общих feature-дубликатов по обе стороны; validation/test преобразовывать таблицей outer-fit. Для пустых категорий использовать prior из соответствующей обучающей части, smoothing=20 зафиксировать заранее. Нативные категории CatBoost и обычный one-hot уже проверены; этот способ кодирования отсутствует. Для групповой схемы потребуется собственная обёртка: sklearn1.5 TargetEncoder не принимает произвольный grouped splitter через cv. Риск — target leakage при неверной реализации.

## HYP-016 — Совместные категории протокола, сервиса и состояния

Классификация, LightGBM: добавить категорию proto×service×state, исходные признаки сохранить. Предположение: совместное состояние соединения лучше различит похожие классы атак. Новизна: это категориальное взаимодействие, не уже проверенные отношения bytes/packets или логарифмы. Значения категорий обучать только на fit, неизвестные комбинации корректно обрабатывать. Критерий — общий grouped Macro F1-порог; дополнительно показать per-class F1. Риск — слишком редкие комбинации.

## HYP-017 — Частотное кодирование сетевых категорий

Классификация, LightGBM: добавить частоты proto/service/state по отдельности и частоту их комбинации. Частота=count/n_fit; невидимым значениям0. Исходные категории оставить, никакие target-статистики не использовать. Предположение: распространённость сетевого поведения даст полезный контекст. Новизна: обучаемые частотные признаки не проверялись; HYP-016 проверяет саму категорию комбинации, здесь добавляются только числовые частоты. Риск — сдвиг частот между train/test. Критерий — общий grouped Macro F1-порог. Требуется fit/transform компонент, это нельзя реализовать независимым row-wise кодом без сохранённого состояния.

## HYP-018 — One-vs-rest вместо общей softmax-модели

Классификация, LightGBM с objective=multiclassova, без class weights и resampling. Предположение: отдельное отделение каждого класса от остальных улучшит распознавание трудных классов. Новизна — разложение многоклассовой задачи; balanced Random Forest уже проверен и не повторяется. Критерий — общий grouped Macro F1-порог. Риск — противоречивые независимые вероятности; правило итогового argmax и mapping classes зафиксировать заранее.

## HYP-019 — Иерархия «норма / атака → тип атаки»

Классификация: новый бинарный LightGBM норма/атака и отдельный LightGBM среди атак. Композиция: P(норма)=1-p_attack; P(класс атаки)=p_attack×p_class_given_attack; итог — argmax совместных вероятностей. Предположение: разделение двух решений уменьшит путаницу между нормой и редкими атаками. Состав меток извлекать из описания конкретной задачи; на других данных стратегию применять только при подтверждённом смысле классов. Новизна: такой архитектуры нет в истории. Риск — ошибки первой ступени влияют на вторую; обязательно учитывать время двух новых моделей и общий grouped Macro F1, не только binary accuracy.

## HYP-020 — Равный вклад групп одинаковых строк

Классификация, LightGBM: каждой training-строке назначить вес1/n_group, где группы рассчитаны по исходным X без id/target только внутри fit. Все строки и конфликтующие метки сохранить; validation не перевзвешивать. Предположение: многочисленные копии частых соединений перестанут чрезмерно влиять на обучение. Новизна: старый grouped split предотвращал пересечение копий через границу, но не менял их вклад в loss. Это не class_weight=balanced: веса зависят от повторяемости X, не частоты класса. Критерий — общий grouped Macro F1-порог; риск — частота копий может отражать реальную частоту поведения и оказаться полезной.
