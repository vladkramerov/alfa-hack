# Контракт платформы и score

Обновлено: 2026-10-23. Основание: исходная презентация Alfa Hack, предоставленная пользователем, и отдельно переданное сообщение организаторов. Сообщение организаторов независимо не сверялось с live-платформой. Ссылки на PDF и локальный снимок сообщения см. в [source manifest](sources/source-manifest.json).

## Запуск и пакет

- Среда: Python 3.12, 8 CPU, 32 GB RAM, не более 3 часов на одну задачу; после лимита оценивается уже сформированный файл.
- Запуск: `python3 solution.py task.md`. `task.md` и входные данные относятся к одной задаче; имена/расположение CSV должны определяться из её описания и доступной schema.
- Обязательный результат: `submission.csv` рядом с `task.md`; до длительного поиска нужен валидный fallback. Перед сохранением проверяются столбцы, число строк, значения/ID и формат предсказаний.
- Решение загружается ZIP до 100 MB. В корне — `solution.py`, неизменённый официальный `requirements.txt` и необходимые `.py` модули; вложенные Python-пакеты и внешние модели/данные не предполагаются. Пакет и импорт из чистой распаковки ещё требуют итогового clean-room подтверждения.
- Не скачивать зависимости и внешние модели при запуске. Не включать в Git/ZIP датасеты, API-ключи или другие секреты.
- API языковой модели использует предоставленные платформой `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`; значения ключей не сохранять. Отсутствующий локальный ключ означает offline proposals, а не проверку реального API.

## Формулы публичного и приватного рейтинга

Формулы ниже проверены визуально по отрендеренным страницам 18–19 исходного PDF. Базовые значения — результат baseline на **той же тестовой выборке**, а не на локальной validation.

Для regression:

`S_reg = 100 × max(0, 1 − RMSE / B_RMSE)`, где `B_RMSE > 0`.

Для multiclass classification:

`S_cls = 100 × max(0, (Macro F1 − B_F1) / (1 − B_F1))`, где `B_F1 < 1`.

Значение на уровне baseline или хуже даёт 0; идеальное значение — 100. Публичный score — среднее арифметическое двух task scores: `Score_public = (S_reg + S_cls) / 2`. Приватный score — среднее task scores двух неизвестных задач: `Score_private = (S_1 + S_2) / 2`; формула task score выбирается по метрике соответствующей задачи.

Значения `B_RMSE` и `B_F1` на скрытом test здесь отсутствуют. Поэтому нельзя переводить локальные RMSE/Macro F1 в score, объяснять ими raw leaderboard числом или выдавать local validation за платформенный результат. Сообщение о leaderboard `579.658` из старого аудита остаётся неинтерпретированным и с диапазоном нормированного score 0–100 не сравнивается без уточнения показателя и версии рейтинга.

## Дополнительные условия и статус проверки

В презентации указано не более 3 отправок в сутки для команды с обновлением в 00:00 МСК. Сообщение организаторов отдельно говорит о лимите в 2 запроса деталей запуска в сутки; начало суток для этого лимита не уточнено. Эти два ограничения относятся к разным действиям.

Локальная новая архитектура, clean-room архив, реальное подключение к API и отправка на Boosters не объявляются принятыми, пока соответствующая проверка не выполнена. Публикация своей Git-ветки разрешена, merge и платформа требуют отдельного решения.
