# SPEC016: новые TabM-гипотезы и улучшенная поставка

Статус: в работе. Прямое разрешение пользователя: «проверяй гипотизы если увеличил метрику то залей на гит ... в комит просто напиши насколько вырос относительно прошлого зип файла метрики». Публикация в ivan_branch разрешена при проверенном выигрыше; повторное согласование не требуется.

REQ-001. Контроль — последний поставленный dist/solution_sergey_ivan_fusion_v1.zip, SHA256 9a3924a53f6bf6191d27dd0717c44afc4137757557e469efe77c3eac28d1756a. Числа H107/H108 из cached разных графов не выдавать за качество этого ZIP. Пользователь прямо поручил сравнение с прежним ZIP: разрешены однократные контрольные fit его реальных моделей на inner/outer в текущей ОС; старые H108 fits не повторяются.
REQ-002. H109 regression: полный TabM с входными/выходными multiplicative adapters и per-member bias в КАЖДОМ hidden layer, обучаемыми piecewise-linear числовыми embeddings по8train-quantile bins; k8,width96,blocks2,dropout.1,60epochs,batch256,AdamW lr.001/wd.0001,seed42,CPU4,≤120sec/neuralfit. Original-y standardized MSE. Это другая модель/представление, не новый backend H108.
REQ-003. H110 classification: та же полная архитектура с train-only inverse-sqrt class weights (нормализация mean sample weight1), CE; явное новое сочетание architecture/embedding/metric-targeting. Все классы сохраняются. Использовать только torch2.5.1 и исходные разрешённые зависимости; tabm пакет не устанавливать.
REQ-004. Одинаковые сохранённые разбиения: H70 regression(inner<4→4,outer<5→5), H78 classification(inner grouped47k→23k,outer grouped70k→17k). Сначала inner: аналитический регрессионный blend[0,1], class grid0/.05/.1/.2/.4/.7/1, strict improvement и положительная доля новой модели. После допуска weight freeze до outer; никакого переотбора по outer. Успех — outer лучше реального прежнего ZIP; без улучшения сохранить старую часть. ≤900sec на каждую гипотезу, с учётом новых научных обучений; техническая подготовка отдельно. Все исходы сразу в results и HYPOTHESES.
REQ-005. При выигрыше собрать переносимый train-only blend: weight вычисляется на внутреннем разбиении train ТЕКУЩЕЙ задачи; в ZIP не вшиваются публичные learned weights/predictions/target. На regression latest-training-period, classification grouped5 fold0; компонент старого ZIP и neural обучаются на prefix, вес выбирается на train-calibration, затем оба full train. Существующие публичные cached модели можно использовать в подготовке без refit при точном совпадении данных/config; runtime умеет обучать с нуля. Fallback при weight0 — прежняя модель.
REQ-006. Экспериментальные outer predictions должны соответствовать этому runtime-графу с train-only выбором веса. При невозможности такого соответствия не публиковать cached gain как улучшение ZIP. Нужны independent replay, snapshots/SHA/fit ledger, labels/schema invariance, unit tests, root-only import, clean CLI и полный technical refit на обеих задачах из чистого ZIP. Архив≤100MB, исходный requirements без изменений. Недопустимо публиковать улучшение без фактической проверки.
REQ-007. Новая поставка отдельно deliveries/torch_tabm_v1 и dist/solution_torch_tabm_v1.zip; старые ZIP/WIP сохранить. В Git только относящиеся к поставке исходники, тесты и доказательства, без data/model caches/секретов/чужих WIP. Push в ivan_branch, без force. Сообщение коммита только «RMSE -X.XXXX%; Macro-F1 +Y.YYYY% vs previous ZIP (local)» с фактически измеренными значениями; скрытый platform score не заявлять.

Выбор агентом: собственная компактная реализация полного TabM на разрешённом torch; официальный tabm требует отдельного неразрешённого package. Дальнейший простой NumPy-mini повтор запрещён журналом. Перенос fresh train calibration важнее копирования прежних fitted coefficients.
