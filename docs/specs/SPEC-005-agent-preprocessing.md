# SPEC-005: обязательная полная предобработка агента

Дата:2026-10-23. Основание: пользователь прямо поручил улучшить обработку данных агентом, обязательно нормализовать, удалять выбросы до5% и приблизить распределения к нормальным. Это новая составная проверка HYP-021; уже проверенный Yeo–Johnson и прежние baseline не запускаются повторно.

## Зафиксированное решение

- REQ-501: агент использует версионированную политику full-v1 для всех новых модельных кандидатов; само имя модели не позволяет обойти обработку. Обучение старых сохранённых конфигураций с прежней обработкой не считать удовлетворением обязательной новой политики; их метрики остаются историческими ориентирами.
- REQ-502: в train-only fit обрабатывать inf→NaN, пустые столбцы/константы, точные дубликаты столбцов, numeric median и индикаторы пропусков; категориальные пропуски — отдельная категория, неизвестные значения допустимы. Цель и ID исключены до обработки. Не удалять признаки только по высокой корреляции/VIF: это уже проверено и ухудшало качество; диагностировать зависимости без безусловного повторения неудачного отбора.
- REQ-503: после imputation непрерывные numeric с>=20 distinct и долей самого частого значения<=0.8 преобразовать QuantileTransformer(output_distribution=normal,n_quantiles=min(512,n_fit),subsample=None,seed42), затем StandardScaler всей числовой части. Дискретные/бинарные признаки не пытаться сделать Gaussian; категории не нормализовать как числа. Все параметры fit только на оставшемся training subset; transform validation/test не refit и сохраняет строки/порядок/индекс. У tied значений и при сдвиге данных точная нормальность не обещается. Значения вне training range обрабатываются конечным квантильным преобразованием; это отличается от прежнего Yeo–Johnson с неустойчивой экстраполяцией.
- REQ-504: IsolationForest100trees,max_samples256,contamination=auto,seed42,threads4 только по числовым X training, без target в detector. Отрицательные decision scores ранжировать, удалить максимум floor(.05*n_fit) строк, не заставляя удалять ровно5%. В классификации дополнительно максимум5% каждого класса и не менее min(50,исходный размер класса) оставшихся; строки редких классов защищены. В regression y не используется для выбора выбросов. Validation/test и строки submission не удалять.
- REQ-505: обучаемая предобработка fit после удаления training-выбросов; detector imputation и модельные imputation/scaling оцениваются отдельно на соответствующих train subset. Сохранять audit очищенных/удалённых признаков, маску исключённых training positions, class counts, долю удаления<=5%, continuous list, missing counts, средние/масштабы и skewness до/после. Нормализация обязательна даже для деревьев по прямому поручению пользователя; полезность определяется метрикой, а не визуальной «нормальностью».
- REQ-506: включить в root-only агент проверенные семейства XGBoost и ExtraTrees log-target, сохранив универсальное определение type/target/id. XGBoost label encoding обратим, log-target только при допустимом y; фиксированные настройки SPEC-004. Конфигурация full-v1 и outlier/target policy входит в fingerprint. Не использовать старые validation scores как score новой обработки; на известных данных хранить обе истории, выбирать только совместимые full-v1 записи. Старые успешные HYP-011…020 fit не повторять.
- REQ-507: HYP-021 — ровно два новых evaluation: full-v1+outliers на ExtraTrees log-target regression против сохранённого RMSE42.19670002719412 и на XGBoost multiclass против Macro F1 0.5914513709191194. Сохранённые outer indices и все validation-строки те же. Сравнение составное; индивидуальные вклады не выдумывать, отрицательные результаты сохранять. Это исследовательская проверка на использованном outer, не независимый test.
- REQ-508: после проверки внедрить политику в оркестратор/worker/history, протестировать протокол, сохранить новый плоский ZIP<=100000000bytes с неизменённым requirements; train-only маски и данные в ZIP не включать. Старый ZIP, удалённый пользователем из рабочего дерева, не восстанавливать поверх удаления: новый пакет получает отдельное имя solution_full_preprocessing.zip. Импорты основного/дочернего процессов, fallback, бюджет, output contract и постоянный hypotheses.json сохраняются.
- REQ-509: ранее запрошенные десять гипотез остаются завершёнными (11метрик,522 независимые проверки); обновить их статусы и отчёт, опубликовать проверенный код в ivan_branch по последнему разрешению пользователя. Отправку на платформу не выполнять; отсутствие реального LLM API явно отмечать.
- REQ-510: по последующему сообщению пользователя о низком платформенном результате устранить конкретные ограничения цикла: выбирать объявленную primary metric из соответствующего раздела/строки, а не первую по глобальному приоритету; дать агенту до12 уникальных опытов и6 LLM cycles в пределах общего времени/лимита токенов, не повторять неизвестные конфигурации при отказе API, сохранять лучший корректный результат после каждого улучшения. Target/data summaries для планирования считать только на fit, не на validation labels. Увеличение лимита не означает расходовать всё время на бесполезные повторы.

Два новых data runs с масками удаления и независимо пересчитанными метриками. Clean ZIP mock HTTP + nested CSV + переименованные target/id + child imports; full refit для выдачи submission не считается повтором validation гипотезы.
