# SPEC-003: платформенный агент и ZIP

Дата: 2026-10-23. Основание: прямое поручение пользователя собрать ZIP <=100 МБ, загрузить на GitHub в ivan_branch, проверять только новые гипотезы и выбирать по метрикам.

## Решение

Плоский пакет solution.py + корневые automl_*.py + неизменённый requirements.txt организаторов.
Оркестратор читает task.md и четыре CSV, определяет target/id/тип/метрику без привязки к публичным именам, немедленно сохраняет корректный резервный ответ.
История известных данных/разбиений/конфигураций встроена в Python-модуль, поскольку JSON/конфиги платформа не копирует.
Совместимые известные метрики используются без переоценки; выбранная конфигурация обучается на всём train для inference, что не является повторной проверкой гипотезы.

Новые проверяемые направления: LightGBM и ExtraTrees. LLM через предоставленные OPENAI_BASE_URL/API_KEY/MODEL анализирует результаты, предлагает новые конфигурации и генерирует ограниченный row-wise Python feature-код; отдельный процесс исполняет его и обучает модель.
Новые параметры выбираются по сохранённой локальной validation; повторные fingerprints и известные направления не запускаются. Время, число опытов, API-запросов и токены ограничены.
После каждого улучшения сохраняется атомарный submission; ошибка worker/LLM не уничтожает последний корректный ответ.
Уточнение пользователя: перед КАЖДОЙ гипотезой читать единый HYPOTHESES.md в проекте; агент читает постоянный hypotheses.json рядом с task.md непосредственно перед допуском каждого кандидата и записывает started до fit, исход после. Журнал разделяет данные/разбиения и сохраняется между запусками.

## Приёмка

- Плоский ZIP <=100 000 000 байт, только root .py и исходный requirements.txt, без данных, моделей и дополнительных зависимостей.
- Запуск `python3 solution.py task.md` из чистой папки с вложенными CSV; проверка основного процесса и дочернего worker.
- Тесты переименованных target/id, регрессии и классификации, неизвестных категорий/пропусков, неверных/двусмысленных путей, формата и порядка submission.
- Тесты timeout/HTTP error/empty choices/truncated output, дубликатов кандидатов и сохранности fallback.
- Локальный OpenAI-compatible стенд доказывает вызов tools, исполнение сгенерированного кода, запись результата; это не проверка реального сервиса Qwen.
- На публичных данных выполняются только новые HYP-009/010; исторические метрики и разбиения сверяются без старых повторных fit-validation.
- Реальные PUBLIC smoke запускают финальное обучение по выбранной конфигурации и проверяют submission, а не повторяют validation известных гипотез.
- GitHub публикация только в ivan_branch, без merge в main и без отправки на соревновательную платформу.

## Ограничения

Ключ, адрес и имя разрешённой LLM в окружении отсутствуют. Реальная интеграция сервиса не считается проверенной до появления платформенных env.
Поддержка неизвестной private-задачи проверяется контрактными примерами; содержимое и метрики private неизвестны.
Выбор по метрикам одного split является локальным выбором, не гарантией скрытого score.

## Фактическая локальная приёмка

30 unit-тестов; clean-extraction4 сценария/7 mock HTTP запросов; финальный full refit из ZIP для обеих задач без повторного validation fit. Доказательства и непроверенные внешние условия: [preflight](../platform-preflight.md). Постоянный hypotheses.json читает история до каждой проверки; HYPOTHESES.md объединяет все известные локальные гипотезы.
