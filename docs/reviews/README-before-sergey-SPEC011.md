## Методика

Выбор preprocessing и силы штрафа выполняется только на inner. Полная outer-панель фиксируется до её первой оценки.
Для регрессии используются годы 1–3 → 4 и 1–4 → 5; для классификации одинаковые строки исходных признаков группируются, чтобы не попадать в train и validation одновременно.
Прежние случайные split из командного журнала напрямую с этими групповыми метриками не сравниваются.

Шаги: imputation/one-hot → корреляционный отбор → VIF → StandardScaler → Yeo–Johnson → предметные признаки.
Нормальность не обязательна для деревьев, а удаление зависимости может ухудшить качество: сохраняются и положительные, и отрицательные результаты.
L2 CatBoost проверяется штатным `l2_leaf_reg`; L1/L2 отдельно сравниваются на Lasso/Ridge и LogisticRegression, поскольку Random Forest таких штрафов не имеет.

## Первая проверяемая гипотеза

Линейная модель лучше постоянного прогноза.
Регрессия: Ridge(alpha=1.0), обучение на Year_Factor 1–4, проверка на 5.
Выбран временной split, поскольку test содержит только Year_Factor=6.
Сравнить rmse с dummy_rmse: меньше — лучше.
Классификация: LogisticRegression, stratified 80/20, random_state=42.
Сравнить macro_f1 с dummy_macro_f1: больше — лучше.

Предобработка обучается только на обучающей части. После оценки модель заново
обучается на всём train, формирует CSV для test и проверяет формат результата.
Целевые значения test неизвестны, локальная валидация не равна оценке платформы.
Обычная LinearRegression оказалась численно нестабильной на временном split;
Ridge остаётся линейной моделью и ограничивает величину коэффициентов.

## Этап 4: ограниченный подбор параметров Optuna

Optuna 4.2.1 — версия из списка организаторов. Подбираем CatBoost для регрессии
и Random Forest для классификации, сохраняя обработку признаков.
Параметры выбираются по внутренней валидации, без использования основной
проверочной выборки в objective Optuna:

- Регрессия: внутри train годы 1–3 → 4; итоговое сравнение по прежнему году 5.
- Классификация: прежние 80% делятся на 75/25; исходные 20% остаются для итога.

До 8 попыток на задачу, включая стартовую конфигурацию. TPESampler(seed=42,
n_startup_trials=4), попытки последовательно, каждая модель до 4 потоков.
Поиск ограничен 420 секундами: текущая попытка может завершиться после лимита;
проверка кандидата и финальное обучение выполняются дополнительно.

## Этап 5: последовательная проверка гипотез

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
python -u hypothesis_suite.py --out runs/hypotheses-20261021-stage5
```

Папка вывода должна быть новой: старые результаты не перезаписываются. Эксперименты
выполняются последовательно, без API. Контрольные модели повторяют прежние настройки
для воспроизводимости и сохранения вероятностей для ансамблей.

1. H1: только class_weight=balanced в Random Forest классификации.
2. H2: нативные категории CatBoost вместо OneHotEncoder, обе задачи. Числовая
   обработка (медиана + масштабирование) и параметры CatBoost сохранены.
3. H3: шесть индикаторов пропусков в регрессии, исходный CatBoost с OneHotEncoder.
4. H4: только нулевой year_built заменён на пропуск, прочее как в контроле CatBoost.
5. H5: четыре отношения трафика/пакетов для исходного леса классификации.
6. H6: равное усреднение исходных леса и CatBoost для каждой задачи. В классификации
   усредняются вероятности, порядок классов явно выровнен. Веса не подбираются.
7. Чувствительность: исходный лидер и сильнейшая новая альтернатива сравниваются
   на другом split. Кандидат фиксируется до просмотра новых результатов.

Основные split не меняются: регрессия годы 1–4 → 5; классификация stratified 80/20,
seed=42. Дополнительные: регрессия 1–3 → 4, классификация seed=2026. Они проверяют
чувствительность, не являются полностью независимым тестом: год 4 уже применялся
во внутреннем подборе Optuna, а случайные split классификации пересекаются.
На дополнительном split выполняется только оценка, без лишнего повторного обучения
на всём train и без нового submission. Все основные эксперименты создают CSV.

Каждый запуск сохраняет JSON с полной конфигурацией, метриками, контрольным запуском,
изменением, временем, commit и SHA-256 данных, id частей, прогнозами validation.
Для классификации сохраняются вероятности и отчёт по классам. Краткие отчёты находятся
в reports/ИМЯ_СЕРИИ/. Для ансамблей отдельно записывается стоимость уже обученных
компонентов: время усреднения нельзя сравнивать со временем полного обучения модели.

### Полная таблица для команды

Главная точка входа — reports/README.md. Полный журнал — reports/EXPERIMENTS.md,
Excel с фильтрами — reports/EXPERIMENTS.xlsx, плоские данные — reports/EXPERIMENTS.csv.
Отдельно отмечаются основная валидация, чувствительность к split, диагностика и повторы.
Все внутренние попытки Optuna сохранены, включая повторившиеся параметры.

```bash
python build_experiment_registry.py
```

Эта команда обновляет Markdown, CSV и JSON из сохранённых источников. Excel — снимок
на дату сборки. publish_results.py также обновляет общий текстовый журнал.
Каждая строка содержит модель, конкретное изменение, основные настройки, split,
измеренные метрики, контроль сравнения, вывод, время, commit и источник. Все параметры
доступны в исходном JSON; в Excel они вынесены на отдельный лист. Старые отсутствующие
метаданные не выдумываются. Ключевые настройки первых линейных моделей восстановлены
по сохранённому коду первого этапа и отмечены соответствующим образом.
