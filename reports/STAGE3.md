# Этап 3 — градиентный бустинг CatBoost

Гипотеза: CatBoost улучшит результаты Random Forest на тех же данных и разделениях.

| Задача | Линейная модель | Random Forest | CatBoost | Лучшая из проверенных |
|---|---:|---:|---:|---|
| Регрессия, RMSE ↓ | 50.079635 | 47.470728 | 45.935836 | CatBoost |
| Классификация, Macro F1 ↑ | 0.428852 | 0.628538 | 0.534100 | Random Forest |

В регрессии гипотеза подтвердилась: ошибка ниже примерно на 3.2% относительно леса.
В классификации эта конфигурация CatBoost проиграла лесу; сохраняем лес как текущий
ориентир. Результат одного эксперимента не означает, что любой бустинг хуже леса.
На скрытом test метрики неизвестны.

## Что именно проверено

CatBoost 1.2.8, 500 итераций, depth=6, learning_rate=0.05, l2_leaf_reg=3.0,
random_seed=42, thread_count=4. Loss: RMSE / MultiClass. Веса классов не менялись.
Подбор параметров и early stopping не использовались.

Предобработка осталась прежней: числовые пропуски — медиана обучающей части,
затем StandardScaler; категории — заполнение константой и OneHotEncoder.
Встроенное кодирование категорий CatBoost в этом эксперименте не используется.
Валидация регрессии: Year_Factor 1–4 → 5. Классификация: stratified 80/20, seed=42.
По каждому id проверено совпадение разделений с лесом, совпадают SHA-256 входных CSV.

Полное время запусков: регрессия 8.49 с, классификация 87.81 с.
Время включает чтение, обучение, валидацию, повторное обучение на всём train и прогноз.
Эти наблюдения получены на одном Mac и не являются отдельным benchmark времени.

## Выводы по ошибкам

В классификации recall у CatBoost: Analysis=0.13, Backdoor=0.09, DoS=0.05, Worms=0.08.
Для леса: 0.16, 0.14, 0.18, 0.54 соответственно. Редкие и сложные классы остаются
важным направлением проверки. По Worms всего 13 примеров в validation, поэтому
показатель этого класса особенно чувствителен к разделению.

Следующий этап согласованного плана — ограниченный подбор параметров через Optuna.
Для регрессии исходный лучший вариант — CatBoost; для классификации — Random Forest.
Обработку категорий и балансировку классов стоит проверять отдельными гипотезами.
Параметры нельзя выбирать по неизвестным ответам test. Повторная оптимизация одной
validation может подогнать решение под неё; финалистов стоит дополнительно проверить
на другом заранее выбранном split или cross-validation, не меняя основную таблицу.

## Повторный запуск

```bash
source .venv/bin/activate
python -m pip install -r requirements-boosting.txt
python -u first_baseline.py regression --model boosting
python -u first_baseline.py multiclass --model boosting
```
