# Alfa Hack — первые эксперименты

Данные по умолчанию читаются из соседней папки `../data_for_participants`.
Исходные данные и baseline организаторов не меняются.

## Запуск на Mac

Нужен Python 3.12. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-local.txt
python -u first_baseline.py regression
python -u first_baseline.py multiclass
```

Если Python 3.12 установлен как `python3.12`, используй его в первой команде.
Другое расположение данных: `--data-dir /путь/data_for_participants`.

Результаты каждого запуска — в отдельной папке `runs/`: метрики `metrics.json`,
предсказания `submission.csv`, состав обучающей и проверочной частей.
Для классификации также сохраняется `classification_report.txt`.

## Первая проверяемая гипотеза

Линейная модель лучше постоянного прогноза.
Регрессия: Ridge(alpha=1.0), обучение на Year_Factor 1–4, проверка на 5.
Выбран временной split, поскольку test содержит только Year_Factor=6.
Сравнить rmse с dummy_rmse: меньше — лучше.
Классификация: LogisticRegression, stratified 80/20, random_state=42.
Сравнить macro_f1 с dummy_macro_f1: больше — лучше.

Предобработка обучается только на обучающей части. После оценки модель заново
обучается на всём train, формирует CSV для test и проверяет формат результата.
Целевые значения test неизвестны, локальная валидация не равна оценке платформы.
Обычная LinearRegression оказалась численно нестабильной на временном split;
Ridge остаётся линейной моделью и ограничивает величину коэффициентов.

## План команды

Линейная модель → Random Forest → бустинг → Optuna. Сравнивать эксперименты на
одних разделениях; фиксировать гипотезу, параметры, метрику, время и commit.
На текущем этапе меняем один фактор за эксперимент. Сначала воспроизводимость,
затем усложнение. Итог хакатона — универсальный LLM-агент, а этот скрипт служит
учебной отправной точкой, не готовым решением для платформы.

Работать и делать коммиты только в sergey_branch. Самостоятельно ветку не менять.

## Этап 2: проверка Random Forest без API

Гипотеза: случайный лес улучшает RMSE / Macro F1 относительно линейных моделей.
Разделения, seed и предобработка оставлены прежними. Используется 150 деревьев,
max_depth=20, min_samples_leaf=2, max_features=0.8, random_state=42, до 4 потоков.
Веса классов не меняются: проверяем замену семейства модели. Используется
scikit-learn из уже установленного минимального списка; новых библиотек не нужно.

```bash
source .venv/bin/activate
python -u first_baseline.py regression --model forest
python -u first_baseline.py multiclass --model forest
```

Режим `--model linear` воспроизводит первый этап; он остаётся режимом по умолчанию.
Один запуск проверяет одну конфигурацию леса. Результат не доказывает превосходство
любого леса над любой линейной моделью и не заменяет оценку скрытого test.

### Как показать результаты команде

Полные результаты сохраняются в `runs/` и исключены из Git. Для короткого отчёта
передайте папку завершённого запуска (путь берите из вывода скрипта):

```bash
python publish_results.py runs/ИМЯ_ПАПКИ_ЗАПУСКА
```

Команда создаёт JSON-отчёт в `reports/` и обновляет таблицу `reports/README.md`.
Там сохраняются метрики, параметры модели, разделение, время, версии и контрольные
суммы данных. В новых запусках также записываются commit и SHA-256 скрипта.
Затем добавьте отчёты в коммит в sergey_branch и отправьте эту ветку на GitHub.
Логи, секреты и CSV с ответами в отчёт не копируются. API/LLM на этом этапе нет.

## Этап 3: градиентный бустинг CatBoost

Используем разрешённый CatBoost 1.2.8. Первая гипотеза: CatBoost улучшит метрики
случайного леса при прежних split, seed и предобработке. Одна фиксированная
конфигурация: 500 итераций, depth=6, learning_rate=0.05, l2_leaf_reg=3,
random_seed=42, thread_count=4. Для регрессии loss=RMSE, для классификации MultiClass.
Без подбора параметров, ранней остановки и изменения весов классов.

```bash
source .venv/bin/activate
python -m pip install -r requirements-boosting.txt
python -u first_baseline.py regression --model boosting
python -u first_baseline.py multiclass --model boosting
```

Категории пока кодируются прежним OneHotEncoder; встроенное кодирование категорий
CatBoost будет отдельной гипотезой. Выборки валидации не меняются. CatBoost выводит
каждые 100 итераций ошибку на обучающих данных (learn); это не результат валидации.
Сравнивать следует итоговые rmse / macro_f1 из metrics.json.

Полные результаты сохраняются в runs/, короткие отчёты добавляются командой
publish_results.py, как на предыдущем этапе. Линейные модели и лес остаются доступны
без установки CatBoost. LLM и API не используются.

Документация библиотеки: https://catboost.ai/docs/en/concepts/python-quickstart
Параметры: https://catboost.ai/docs/en/references/training-parameters/
